# Quenchworks volcano

[Volcano](https://github.com/volcano-sh/volcano) 1.16.0 on the QuenchWorks image
(built from source, nonroot, CVE-gated at build, pinned by digest, cosign-signed).
Volcano is a batch scheduler for AI, ML and HPC workloads: gang scheduling (all
tasks of a job start together or none do), queues with fair share, and `Job`,
`Queue` and `PodGroup` resources.

The chart installs the 12 Volcano CRDs, the scheduler, the controllers and the
admission webhook manager (one image, a different binary per Deployment),
upstream's RBAC and configuration, and the webhook configurations.

## Install

```bash
helm install volcano oci://ghcr.io/quenchworks/charts/volcano -n volcano-system --create-namespace
```

Then a gang-scheduled job:

```yaml
apiVersion: batch.volcano.sh/v1alpha1
kind: Job
metadata: { name: train }
spec:
  minAvailable: 4
  schedulerName: volcano
  queue: default
  tasks:
    - replicas: 4
      name: worker
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: worker
              image: your/training-image
```

## Notes

- One install per cluster: the resources keep upstream's names
  (`volcano-scheduler`, `volcano-controllers`, `volcano-admission`), and the
  webhook manager is told the fixed Service name `volcano-admission-service`.
  Install into any namespace; the webhooks skip that namespace and `kube-system`.
- The admission certificate (Secret `volcano-admission-secret`) is generated by
  the chart once and kept across upgrades, in place of upstream's init Job, which
  needs kubectl and openssl. The webhook manager also writes the CA into the
  webhook configurations at startup.
- The scheduler and controller settings are upstream's defaults
  (`volcano-scheduler-configmap`, `volcano-admission-configmap`).
- Helm installs the CRDs on first install and never upgrades or deletes them.
  Apply the new `crds/` yourself before upgrading across Volcano releases.
