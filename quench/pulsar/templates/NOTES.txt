Quenchworks Apache Pulsar is installed as {{ include "quench-common.fullname" . }}
(single-node standalone: broker + in-process BookKeeper + embedded RocksDB metadata).

Service DNS (inside the cluster):

  binary protocol : {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.pulsarPort }}
  HTTP admin/REST : {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.httpPort }}

Check broker health (HTTP REST, unauthenticated):

  curl http://{{ include "quench-common.fullname" . }}:{{ .Values.service.httpPort }}/admin/v2/brokers/health   # -> ok
  curl http://{{ include "quench-common.fullname" . }}:{{ .Values.service.httpPort }}/admin/v2/clusters         # -> ["standalone"]

Produce and consume a message (the runtime image ships the CLI clients):

  POD={{ include "quench-common.fullname" . }}-0
  kubectl exec "$POD" -- /opt/pulsar/bin/pulsar-client produce \
    -m 'hello-quench' -n 1 persistent://public/default/demo
  kubectl exec "$POD" -- /opt/pulsar/bin/pulsar-client consume \
    -s sub -n 1 -p Earliest persistent://public/default/demo

Administer topics/tenants/namespaces via the admin CLI or the REST API:

  kubectl exec "$POD" -- /opt/pulsar/bin/pulsar-admin topics list public/default
  kubectl exec "$POD" -- /opt/pulsar/bin/pulsar-admin clusters list

SECURITY: Pulsar ships no authentication. This deployment relies on the NetworkPolicy
(networkPolicy.enabled=true, allowExternal=false) as its trust boundary -- ingress on
6650 + 8080 is restricted to in-cluster pods. There is no Secret. Do not expose Pulsar
externally without an authenticating proxy.

The image is pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
