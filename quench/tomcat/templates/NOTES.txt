Quenchworks Apache Tomcat is installed as {{ include "quench-common.fullname" . }}.

Reach it from inside the cluster (HTTP on port {{ .Values.service.port }}):

  Endpoint: {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}

  kubectl run web-test --rm -it --image=curlimages/curl --restart=Never -- \
    curl -s -o /dev/null -w '%{http_code}\n' http://{{ include "quench-common.fullname" . }}:{{ .Values.service.port }}/
  # A 404 is expected and healthy: the default ROOT webapp is emptied, so Tomcat
  # (Coyote) answers but has nothing to serve at /. Deploy a WAR to change this.

Or port-forward from your workstation:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} 8080:{{ .Values.service.port }}
  curl -i http://127.0.0.1:8080/

Deploy an application by baking your WAR into a derived image, or by mounting it
into the Tomcat webapps directory via extraVolumes / extraVolumeMounts.

The image is nonroot (uid 1001), runs on a read-only root filesystem (an emptyDir
is mounted writable at /tmp for Tomcat's logs, temp and work dirs under
/tmp/tomcat), pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
