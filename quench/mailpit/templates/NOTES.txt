Quenchworks Mailpit is installed as {{ include "quench-common.fullname" . }}.

Point your application's SMTP client at:

  host: {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local
  port: {{ .Values.service.ports.smtp }}   (no TLS, no authentication)

and read the captured mail over a port-forward:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} {{ .Values.service.ports.http }}:{{ .Values.service.ports.http }}
  # UI:  http://127.0.0.1:{{ .Values.service.ports.http }}{{ .Values.ui.webroot }}
  # API: http://127.0.0.1:{{ .Values.service.ports.http }}{{ trimSuffix "/" .Values.ui.webroot }}/api/v1/messages

!! MAILPIT IS A DEVELOPMENT / TEST MAIL SINK !!
The SMTP listener on port {{ .Values.smtp.port }} accepts mail from ANY client that can
reach it, with no authentication and no TLS, for ANY recipient, and never delivers
it onward -- every message just lands in the inbox above. Anyone who reaches the
UI port can then read all of it. Never point production traffic at it and never
expose it to an untrusted network.
{{- if .Values.networkPolicy.enabled }}
{{- if .Values.networkPolicy.allowExternal }}

  networkPolicy.allowExternal is TRUE: every pod in the cluster can submit mail to
  this instance and read the inbox. Set it to false to confine both listeners to
  namespace {{ .Release.Namespace }}.
{{- else }}

  The NetworkPolicy restricts both listeners to pods in namespace {{ .Release.Namespace }}.
{{- end }}
{{- else }}

  networkPolicy.enabled is FALSE: nothing restricts who can reach either listener.
{{- end }}
{{- if not (include "mailpit.authEnabled" .) }}

  The web UI and REST API are UNAUTHENTICATED. Set auth.username / auth.password
  (or auth.existingSecret) before exposing them, e.g. through an Ingress.
{{- end }}

{{ if .Values.persistence.enabled }}
Messages are stored in {{ .Values.persistence.path }}/mailpit.db on a PersistentVolumeClaim
and survive pod restarts (up to smtp.maxMessages = {{ .Values.smtp.maxMessages }} messages).
{{- else }}
Messages are stored in {{ .Values.persistence.path }}/mailpit.db on an ephemeral emptyDir and
are LOST on pod restart -- usually what you want for a test mailbox. Set
persistence.enabled=true to keep them.
{{- end }}

Mailpit keeps one inbox in one SQLite database on one pod, so keep replicaCount at 1.

The image is pinned by digest and signed. Verify it:

  cosign verify ghcr.io/quenchworks/images/mailpit \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
