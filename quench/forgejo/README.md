# Quenchworks forgejo

Hardened [Forgejo](https://forgejo.org/), a self-hosted Git forge and community
[Gitea](https://about.gitea.com/) fork, on a minimal, nonroot, 0-CVE image pinned
by digest and cosign-signed (keyless / Sigstore). Single node; it persists its
repositories, SQLite database and generated config to a PVC, and boots
install-locked so the web installer is never served.

## Install

```bash
helm install my-forgejo oci://ghcr.io/quenchworks/charts/forgejo
```

Then port-forward and open the web UI:

```bash
kubectl port-forward svc/my-forgejo-forgejo 3000:80
# http://127.0.0.1:3000
```

Set the external URL (behind an ingress) and open ingress to clients outside the
release namespace:

```bash
helm install my-forgejo oci://ghcr.io/quenchworks/charts/forgejo \
  --set config.rootUrl=https://git.example.com/ \
  --set networkPolicy.allowExternal=true
```

## Verify the image

```bash
cosign verify ghcr.io/quenchworks/images/forgejo \
  --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Each build also ships an SPDX SBOM and SLSA provenance attestation. Verify them
with `gh attestation verify oci://ghcr.io/quenchworks/images/forgejo --owner quenchworks`.

## Architecture

Forgejo runs as a single-replica StatefulSet. Everything lives locally: a SQLite
database, a repository tree, and the generated `app.ini`, all on one PVC mounted
at `persistence.mountPath` (`/data`) via a `volumeClaimTemplate`. Because state is
local it cannot be horizontally scaled, so `replicaCount` is capped at 1.

The container runs nonroot (uid 1001) on a read-only root filesystem with all
capabilities dropped; only the `/data` PVC and an emptyDir `/tmp` are writable.
Forgejo serves `/api/healthz` (returns `{"status":"pass",...}`), which backs the
startup, liveness and readiness probes.

The hardened image runs `forgejo web` directly and has no `environment-to-ini`
step, so `FORGEJO__*` env vars are not honored. Instead an init container
generates an `app.ini` on the PVC on first boot, containing:

- `INSTALL_LOCK = true`, which skips the web installer
- `SECRET_KEY`, `INTERNAL_TOKEN` and `oauth2.JWT_SECRET`, generated by the forgejo
  binary itself (real, valid values) and persisted on the PVC, so they never touch
  the read-only root filesystem and never rotate on restart
- a SQLite DB at `<mountPath>/forgejo.db`, repos under
  `<mountPath>/git/repositories`

The file is written only if absent, so restarts and upgrades keep your data and
secrets. To change non-secret settings, edit `config.*` in values.

## Configuration examples

Registration is open by default. Create the first admin non-interactively:

```bash
kubectl exec -it my-forgejo-forgejo-0 -- \
  forgejo --config /data/app.ini admin user create \
  --admin --username admin --password 'change-me' --email admin@example.com
```

Serve behind an ingress on a larger volume, with git-over-SSH enabled:

```yaml
config:
  rootUrl: https://git.example.com/
  ssh:
    enabled: true
    port: 22
persistence:
  size: 20Gi
  storageClass: fast-ssd
```

When SSH is enabled you must also expose the SSH port through the service/ingress
yourself.

## Uninstall

```bash
helm uninstall my-forgejo
```

The PVC provisioned by the StatefulSet's `volumeClaimTemplate` is retained on
uninstall. Delete it explicitly to remove the repositories, database and secrets:

```bash
kubectl delete pvc -l app.kubernetes.io/instance=my-forgejo
```

## Notes

Single node only: Forgejo stores everything in a local SQLite database plus a
repository tree on the PVC, so it cannot be horizontally scaled. For HA you would
move to an external database and shared storage, tracked as a follow-up. The chart
depends on the `quench-common` library chart, pulled from
`oci://ghcr.io/quenchworks/charts/quench-common`.
