Quenchworks forgejo is installed as {{ include "quench-common.fullname" . }}.

Reach the web UI / API from inside the cluster:

  http://{{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}

Port-forward it to your laptop:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} 3000:{{ .Values.service.port }}
  # then open http://127.0.0.1:3000

Health check:

  curl http://127.0.0.1:3000/api/healthz   # -> {"status":"pass",...}

Forgejo boots install-locked: no web installer is served. An init container
seeds an app.ini (with fresh SECRET_KEY / INTERNAL_TOKEN / oauth2 JWT_SECRET
generated by the forgejo binary) onto the PVC on first start, so those secrets
persist across restarts. Repos, the SQLite DB and config all live on the PVC at
{{ .Values.persistence.mountPath }}.

Create the first admin user (registration is open by default, or run):

  kubectl exec -it {{ include "quench-common.fullname" . }}-0 -- \
    forgejo --config {{ .Values.persistence.mountPath }}/app.ini admin user create \
    --admin --username admin --password 'change-me' --email admin@example.com

Set config.rootUrl to your external URL when placing Forgejo behind an Ingress
so clone URLs and links are correct.

The image is pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
