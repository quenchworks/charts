Quenchworks External Secrets Operator is installed as {{ include "quench-common.fullname" . }}.

It runs three deployments off the single ESO image:

  {{ include "external-secrets.controllerName" . }}       reconcile loop
  {{ include "external-secrets.webhookName" . }}          validating webhook (:443 -> {{ .Values.webhook.port }})
  {{ include "external-secrets.certControllerName" . }}   webhook CA generation + caBundle injection

No cert-manager is required: the cert-controller generates the webhook's
self-signed CA, stores it in the Secret {{ include "external-secrets.webhookCertSecretName" . }},
and injects the caBundle into the ValidatingWebhookConfigurations.

The CRDs (ExternalSecret, SecretStore, ClusterSecretStore, PushSecret, ...) are
installed from the chart's crds/ directory.

Try it with the built-in fake provider (no external system needed):

  kubectl apply -n {{ .Release.Namespace }} -f - <<'EOF'
  apiVersion: external-secrets.io/v1
  kind: SecretStore
  metadata:
    name: fake
  spec:
    provider:
      fake:
        data:
          - key: "/example"
            value: "hello"
  ---
  apiVersion: external-secrets.io/v1
  kind: ExternalSecret
  metadata:
    name: example
  spec:
    refreshInterval: 1h
    secretStoreRef:
      name: fake
      kind: SecretStore
    target:
      name: example-secret
    data:
      - secretKey: greeting
        remoteRef:
          key: "/example"
  EOF

  kubectl get secret -n {{ .Release.Namespace }} example-secret -o jsonpath='{.data.greeting}' | base64 -d

The image is pinned by digest and signed. Verify it:

  cosign verify ghcr.io/quenchworks/images/external-secrets \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
