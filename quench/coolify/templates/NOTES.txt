HOW COOLIFY WORKS (read this)
  Coolify is a CONTROL PLANE. It does NOT schedule your workloads on Kubernetes — it
  manages EXTERNAL Docker hosts over SSH. This chart runs only the control plane (app +
  realtime + Postgres + Redis) in the cluster. The build/deploy tier (the coolify-helper
  build engine and the per-server proxy) runs ON the managed Docker hosts; Coolify pulls
  and runs it there over SSH. That helper is PRIVILEGED by design (it drives the host's
  Docker daemon) and is therefore intentionally NOT a Deployment in this chart.

    # Healthcheck: curl http://127.0.0.1:8080/healthcheck   (-> "OK")
  Set app.url (or enable ingress) to your real public URL so Coolify builds correct links.
{{- end }}

ON FIRST BOOT
  The app runs database migrations + seeder + app:init (artisan) before php-fpm serves
  /healthcheck 200, so the first rollout takes a few minutes. Horizon (queue workers) and
  the scheduler start alongside it.

CONNECTING A SERVER TO MANAGE
  In the UI, add a Server by its SSH host + the key Coolify generates (stored under the
  persistent storage volume at storage/app/ssh). Coolify then installs/runs its
  helper + proxy on THAT host. Those host-side components are privileged by design.
