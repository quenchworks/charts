Quenchworks PostgreSQL is installed as {{ include "quench-common.fullname" . }}.
{{- if eq .Values.architecture "replication" }}

Topology: Patroni HA — {{ .Values.ha.replicaCount }} members, one elected leader +
streaming replicas, automatic failover through the Kubernetes API (no external etcd).

Connect from inside the cluster:

  Read/write (leader):  {{ include "postgresql.primaryName" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}
                        (or {{ include "quench-common.fullname" . }} — same leader)
  Read-only (replicas): {{ include "postgresql.replicaName" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}
  User: {{ .Values.auth.username }}
  Database: {{ .Values.auth.database | default .Values.auth.username }}

Inspect the cluster (roles, replication lag, failover):

  kubectl exec -n {{ .Release.Namespace }} {{ include "quench-common.fullname" . }}-0 -- patronictl list

Kill the leader and Patroni promotes a replica within a few seconds; the primary
Service follows the new leader automatically. A voluntary drain is capped by the
PodDisruptionBudget (minAvailable: {{ .Values.ha.podDisruptionBudget.minAvailable }}) so it can never break quorum.
{{- else }}

  Port: {{ .Values.service.port }}
  User: {{ .Values.auth.username }}
  Database: {{ .Values.auth.database | default .Values.auth.username }}
{{- end }}

{{- if .Values.auth.enabled }}

Get the password:

  kubectl get secret --namespace {{ .Release.Namespace }} {{ include "postgresql.secretName" . }} \
    -o jsonpath="{.data.{{ include "postgresql.secretPasswordKey" . }}}" | base64 -d

Then, from a client pod:

  PGPASSWORD="<password>" psql -h {{ include "quench-common.fullname" . }} -U {{ .Values.auth.username }}
{{- else }}

WARNING: auth is disabled.
{{- end }}

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
