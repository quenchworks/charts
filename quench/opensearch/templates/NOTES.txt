{{- if eq .Values.mode "ha" }} in HA mode: {{ .Values.master.replicaCount }} cluster-manager node(s) + {{ .Values.data.replicaCount }} data node(s).{{ else }} in single-node mode (no fault tolerance).{{ end }}

{{- if not .Values.service.enabled }}

service.enabled is false: the chart created no client Service. Front the pods with
your own Service{{ if include "quench-common.tls.enabled" . }} (target port "https", 8443 on the TLS sidecar){{ end }}.
{{- else if include "quench-common.tls.enabled" . }}

Query the HTTPS API from inside the cluster (OpenSearch HTTP is bound to loopback; an
nginx sidecar terminates TLS). Trust the CA in Secret {{ include "quench-common.tls.secretName" . }}:

  curl --cacert ca.crt https://{{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.httpsPort }}/_cluster/health
{{- else }}

Query the HTTP API from inside the cluster:

  curl http://{{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.httpPort }}/_cluster/health
{{- end }}

{{- if eq .Values.mode "ha" }}

Wait for the cluster to form, then check it is green/yellow with all nodes joined:

  curl '.../_cluster/health?pretty'          # status + number_of_nodes
  curl '.../_cat/nodes?v&h=name,node.role,cluster_manager'

New indices default to 1 replica, so with >= 2 data nodes a shard's replica lives
on a different node and survives one data-node loss. Cluster-manager election is
native: lose a master and the remaining {{ sub (int .Values.master.replicaCount) 1 }} re-elect a leader as long as a
quorum ({{ add (div (int .Values.master.replicaCount) 2) 1 }}) survives. Losing the master quorum is NOT auto-recovered
(split-brain guard) -- restore the failed masters and they rejoin.
{{- end }}
