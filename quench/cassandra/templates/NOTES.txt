Quenchworks Cassandra is installed as {{ include "quench-common.fullname" . }}.

Connect over CQL from inside the cluster (port {{ .Values.service.cqlPort }}):

  CQL service: {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.cqlPort }}

The runtime image has no usable cqlsh (no Python), so connect with a throwaway
upstream client pod:

  kubectl run cqlclient --rm -it --restart=Never --image=cassandra:5.0 -- \
    cqlsh {{ include "quench-common.fullname" . }} {{ .Values.service.cqlPort }}
{{- if .Values.auth.enabled }}

Authentication is ENABLED. Cassandra bootstrapped the default superuser
`cassandra` / `cassandra` — log in, then immediately rotate it:

  kubectl run cqlclient --rm -it --restart=Never --image=cassandra:5.0 -- \
    cqlsh {{ include "quench-common.fullname" . }} {{ .Values.service.cqlPort }} -u cassandra -p cassandra

  ALTER ROLE cassandra WITH PASSWORD = '<new-strong-password>';

For clusters also raise the system_auth keyspace replication factor:

  ALTER KEYSPACE system_auth WITH replication =
    {'class':'NetworkTopologyStrategy','<dc>':{{ .Values.replicaCount }}};
{{- else }}

Authentication is OFF (AllowAllAuthenticator). Enable it with:

  --set auth.enabled=true

then rotate the bootstrapped cassandra/cassandra superuser (see the chart README).
{{- end }}

Check ring status (a pod becomes Ready only when nodetool reports it Up/Normal):

  kubectl exec {{ include "quench-common.fullname" . }}-0 -- nodetool status

The image is pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
