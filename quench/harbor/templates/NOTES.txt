{{- else if .Values.proxy.enabled }}

INGRESS IS DISABLED. The whole app is still reachable through ONE front-door Service —
the "harbor" proxy Service — which routes "/" to the UI and the API/docker paths to core.
Port-forward THAT service (not core/portal):
  kubectl port-forward --namespace {{ .Release.Namespace }} svc/{{ include "harbor.proxy" . }} 8080:{{ .Values.proxy.service.port }}
  # Web UI:      open http://127.0.0.1:8080/ and log in as admin
  # API health:  curl http://127.0.0.1:8080/api/v2.0/health
  # docker login / push/pull also go through 127.0.0.1:8080.
{{- else }}

INGRESS AND PROXY ARE DISABLED. Reach the API/UI by port-forwarding the core + portal
Services separately (no unified front door):
  kubectl port-forward --namespace {{ .Release.Namespace }} svc/{{ include "harbor.core" . }} 8080:{{ .Values.core.service.port }}
  # API health:  curl http://127.0.0.1:8080/api/v2.0/health
  # set externalURL to your real front door so docker login works.
{{- end }}

DOCKER LOGIN + PUSH/PULL
  docker login {{ trimPrefix "http://" (trimPrefix "https://" (include "harbor.externalURL" .)) }}
  # then tag and push into a project (create a project first in the UI or via the API):
  docker tag alpine:latest {{ trimPrefix "http://" (trimPrefix "https://" (include "harbor.externalURL" .)) }}/library/alpine:latest
  docker push {{ trimPrefix "http://" (trimPrefix "https://" (include "harbor.externalURL" .)) }}/library/alpine:latest
  docker pull {{ trimPrefix "http://" (trimPrefix "https://" (include "harbor.externalURL" .)) }}/library/alpine:latest
  The token service (signed with an RSA key generated and persisted by this chart)
  is the trust anchor for these pulls/pushes — core issues bearer tokens the registry
  honours over htpasswd basic auth.
