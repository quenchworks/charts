Quenchworks MySQL is installed as {{ include "quench-common.fullname" . }}.

Connect from inside the cluster:

  Host: {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local
  Port: {{ .Values.service.port }}
{{- if .Values.auth.database }}
  Database: {{ .Values.auth.database }}
{{- end }}

Get the root password:

  kubectl get secret --namespace {{ .Release.Namespace }} {{ include "mysql.secretName" . }} \
    -o jsonpath="{.data.{{ include "mysql.rootPasswordKey" . }}}" | base64 -d

Then, from a client pod:

  mysql -h {{ include "quench-common.fullname" . }} -uroot -p"<root-password>"
{{- if eq .Values.architecture "group-replication" }}

High availability: MySQL Group Replication, single-primary ({{ .Values.ha.replicaCount }} members).
  Read/write (primary): {{ include "quench-common.fullname" . }}
  Read-only (secondaries): {{ include "mysql.readonlyName" . }}

Inspect the group from any member:

  kubectl exec {{ include "quench-common.fullname" . }}-0 --namespace {{ .Release.Namespace }} -- \
    mysql -uroot -p"<root-password>" \
    -e "SELECT MEMBER_HOST, MEMBER_STATE, MEMBER_ROLE FROM performance_schema.replication_group_members"
{{- end }}

The image is pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
