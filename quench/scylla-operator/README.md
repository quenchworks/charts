# Quenchworks ScyllaDB Operator

Hardened [ScyllaDB Operator](https://github.com/scylladb/scylla-operator): runs ScyllaDB clusters on Kubernetes from
`ScyllaCluster` resources (racks, scaling, rolling upgrades, repairs and backups with Scylla Manager). The image builds
the operator from the release tag as one static binary, which also serves the admission webhook and the sidecar that
runs inside ScyllaDB pods; it is CVE-gated at build, cosign-signed and pinned by digest.

The chart installs the operator's CRDs, its ClusterRoles (upstream's, unchanged), the operator and the webhook server.
The webhook's CA and serving certificate are generated by Helm and kept across upgrades, so cert-manager is not
required.

## Install

```bash
helm install scylla-operator oci://ghcr.io/quenchworks/charts/scylla-operator -n scylla-operator --create-namespace
```

Install it once per cluster: the ClusterRoles are cluster-scoped.

## ScyllaDB image

The operator starts ScyllaDB through upstream's image entrypoint (`/docker-entrypoint.py`) inside each ScyllaDB pod.
The QuenchWorks `scylladb` image is laid out differently and does not provide it yet, so a `ScyllaCluster` needs an
image with the upstream layout in `spec.repository` until it does.

## Configuration

| Value | Default | Notes |
|---|---|---|
| `logLevel` | `2` | Operator and webhook verbosity (0-10) |
| `operator.replicaCount` | `1` | Leader election lets you run more |
| `webhook.replicaCount` | `1` | Webhook server replicas |

## Verify the image

```bash
cosign verify ghcr.io/quenchworks/images/scylla-operator \
  --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```
