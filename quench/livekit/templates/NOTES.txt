Quenchworks LiveKit is installed as {{ include "quench-common.fullname" . }}.

The server runs nonroot and serves HTTP/WebSocket signaling + health on container
port 7880, with RTC/TCP fallback on 7881. The Service exposes:

  {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}   (signaling / health)
  {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.rtcTcpPort }}   (rtc-tcp)

Check health over a port-forward ("GET /" returns 200 "OK" once the server is up):

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
  curl http://127.0.0.1:{{ .Values.service.port }}/

This is a SINGLE-NODE deployment (no Redis). Media flows over WebRTC UDP, which is
not surfaced on the ClusterIP Service. For production:
  - add Redis and run multiple replicas for horizontal scale;
  - expose the RTC UDP port range (and TCP 7881 / a TURN server) via a
    LoadBalancer or host networking so clients can reach media.
See https://docs.livekit.io/home/self-hosting/deployment/ for the full topology.

The image is pinned by digest and signed. Verify it:

  cosign verify ghcr.io/quenchworks/images/livekit \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
