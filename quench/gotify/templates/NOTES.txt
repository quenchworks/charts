Quenchworks gotify is installed as {{ include "quench-common.fullname" . }}.
{{- if include "quench-common.tls.enabled" . }}

TLS is on: Gotify serves HTTPS itself (native TLS) on Service port {{ .Values.service.httpsPort }},
which replaces the plain-HTTP port in the URLs below:

  https://{{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local{{ if ne (int .Values.service.httpsPort) 443 }}:{{ .Values.service.httpsPort }}{{ end }}/health

The certificate is in Secret {{ include "quench-common.tls.secretName" . }}; trust its ca.crt (self-signed by default):

  kubectl get secret --namespace {{ .Release.Namespace }} {{ include "quench-common.tls.secretName" . }} -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt
  kubectl port-forward --namespace {{ .Release.Namespace }} svc/{{ include "quench-common.fullname" . }} 8443:{{ .Values.service.httpsPort }}
  curl --cacert ca.crt https://localhost:8443/health
{{- end }}

Reach the web UI / API from inside the cluster:

  http://{{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}

Port-forward it to your laptop:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} 8080:{{ .Values.service.port }}
  # then open http://127.0.0.1:8080

Health check:

  curl http://127.0.0.1:8080/health   # -> {"health":"green","database":"green"}

Default login is admin / admin unless you set GOTIFY_DEFAULTUSER_NAME /
GOTIFY_DEFAULTUSER_PASS (via extraEnvVars or a Secret). CHANGE THE PASSWORD
AFTER FIRST LOGIN under User settings.

Data (SQLite DB + uploaded images + plugins) persists on the PVC at /app/data.

The image is pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
