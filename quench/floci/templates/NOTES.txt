Quenchworks Floci (local AWS emulator, LocalStack-compatible) is installed as
{{ include "quench-common.fullname" . }}.
{{ if include "floci.fullMode" . }}
============================================================================
  !!!  WARNING: FLOCI IS RUNNING IN FULL MODE -- THIS IS NOT HARDENED  !!!
============================================================================
  This release runs the `floci-full` image as ROOT (runAsNonRoot=false) with
  the host Docker socket /var/run/docker.sock BIND-MOUNTED into the pod, and
  the read-only root filesystem DISABLED. This is what enables all 65 services
  including the 10 Docker-backed ones (Lambda, RDS, ElastiCache, MSK, ECS, EKS,
  OpenSearch, ECR, DocumentDB, Neptune).

  A mounted host Docker socket is a NODE-ROOT / CONTAINER-ESCAPE surface: any
  code in this pod can control the node's Docker daemon and effectively owns the
  node. DO NOT use full mode on shared or multi-tenant clusters. It is an opt-in
  developer/CI convenience only. Switch back with floci.mode=hardened.
============================================================================
{{ end }}
{{ if include "floci.fullMode" . -}}
Floci is running as ROOT with the host Docker socket mounted (full mode). The Service exposes one port:
{{- else -}}
Floci runs nonroot on a read-only root filesystem. The Service exposes one port:
{{- end }}

  http  {{ .Values.service.port }}  LocalStack-compatible edge/API + /_floci/health

  {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local

SUPPORTED SERVICES (in-process only): S3, DynamoDB, SQS, SNS, IAM.
NOT SUPPORTED here: the Docker-backed services (Lambda, RDS, ECS, EKS, ...),
which require the host Docker socket + root and are incompatible with this
hardened nonroot image.

Check health and point an AWS client at Floci over a port-forward:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
  curl http://127.0.0.1:{{ .Values.service.port }}/_floci/health
  aws --endpoint-url http://127.0.0.1:{{ .Values.service.port }} s3 mb s3://demo

{{ if .Values.persistence.enabled -}}
Persistence is ENABLED (FLOCI_STORAGE_MODE={{ .Values.floci.storage.mode }}); state
is written to a PVC at {{ .Values.floci.storage.path }}. This is single-replica
durability only, not a scale-out mechanism -- keep replicaCount at 1.
{{- else -}}
Storage is IN-MEMORY (FLOCI_STORAGE_MODE={{ .Values.floci.storage.mode }}): all
S3/DynamoDB/SQS/SNS/IAM state is lost on restart. This is the default and is fine
for ephemeral dev/test. To persist across restarts, set persistence.enabled=true
and floci.storage.mode to persistent/hybrid/wal (single replica only).
{{- end }}

The image is pinned by digest and signed. Verify it:

  cosign verify ghcr.io/quenchworks/images/floci \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
