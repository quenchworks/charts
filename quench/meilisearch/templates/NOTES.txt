Quenchworks Meilisearch is installed as {{ include "quench-common.fullname" . }} (single-node).

The search API is reachable inside the cluster at:

  http://{{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ .Values.service.port }}

Health (always UNAUTHENTICATED, used by the probes):

  curl http://{{ include "quench-common.fullname" . }}:{{ .Values.service.port }}/health   # -> {"status":"available"}

AUTH MODEL: this chart runs Meilisearch with MEILI_ENV=production, so a master key is
MANDATORY. Every API route except GET /health requires:

    Authorization: Bearer <master-key>

{{- if .Values.auth.existingSecret }}
The master key comes from your existing Secret "{{ .Values.auth.existingSecret }}" (key "{{ .Values.auth.existingSecretKey }}").

  KEY="$(kubectl get secret {{ .Values.auth.existingSecret }} -o jsonpath='{.data.{{ .Values.auth.existingSecretKey }}}' | base64 -d)"
{{- else }}
The master key lives in the chart-managed Secret. Pull it out with:

  KEY="$(kubectl get secret {{ include "meilisearch.secretName" . }} -o jsonpath='{.data.master-key}' | base64 -d)"
{{- end }}

Port-forward to reach it from your workstation:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}

NOTE: the mini-dashboard web UI is bundled in the image, but Meilisearch serves it at /
only in MEILI_ENV=development. This chart runs MEILI_ENV=production, where the dashboard
is intentionally hidden and GET / returns {"status":"Meilisearch is running"}. Drive the
search API directly with the curl examples below (all WITH the master key).

Create an index, add a document, then search (all WITH the master key):

  # 1) create an index keyed on "id"
  curl -fsS -X POST "http://127.0.0.1:{{ .Values.service.port }}/indexes" \
    -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
    -d '{"uid":"movies","primaryKey":"id"}'

  # 2) add documents (async task; Meilisearch indexes in the background)
  curl -fsS -X POST "http://127.0.0.1:{{ .Values.service.port }}/indexes/movies/documents" \
    -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
    -d '[{"id":1,"title":"Interstellar"},{"id":2,"title":"Inception"}]'

  # 3) typo-tolerant search (note the typo "interstelar" still matches)
  curl -fsS -X POST "http://127.0.0.1:{{ .Values.service.port }}/indexes/movies/search" \
    -H "Authorization: Bearer $KEY" -H 'content-type: application/json' \
    -d '{"q":"interstelar"}'

A request WITHOUT the key (or with a wrong key) is rejected with 401/403 -- proving the
generated master-key Secret is wired through. The /health route stays open so probes work.

This chart runs Meilisearch as a single node (one StatefulSet replica with local LMDB
storage). The OSS engine has no built-in clustering; keep replicaCount at 1.

The image is pinned by digest and signed. Verify it:

  cosign verify {{ .Values.image.repository }} \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
