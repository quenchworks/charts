# Quenchworks KServe

[KServe](https://kserve.github.io/website/) serves machine-learning models on
Kubernetes from `InferenceService` resources. This chart installs the KServe
controller in **Standard** mode: each InferenceService becomes a plain
Deployment and Service, so it needs neither Knative, Istio nor cert-manager.
The CRDs ship in `crds/`, and the webhook certificate is generated by Helm and
kept across upgrades.

## Install

```bash
helm install kserve oci://ghcr.io/quenchworks/charts/kserve -n kserve --create-namespace
```

## Serve a model

```yaml
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: my-model
spec:
  predictor:
    containers:
      - name: kserve-container
        image: <your model server image>
```

## Notes

- Install one KServe per cluster: the webhook configurations and CRDs are
  cluster-wide.
- No ingress is created (`disableIngressCreation`); expose `<name>-predictor`
  with your own Ingress or Gateway.
- The built-in serving runtimes (ClusterServingRuntimes for sklearn, xgboost,
  huggingface, ...) are not included and have no QuenchWorks images yet. Bring
  your own container, as above.
- The agent, router and storage-initializer images in `inferenceservice-config`
  are upstream's; KServe pulls them only for request logging, batching,
  inference graphs and `storageUri` downloads.
- Helm installs CRDs from `crds/` but never upgrades them; apply the new files
  by hand when you upgrade.
