Quenchworks Jenkins (CI/CD automation server) is installed as {{ include "quench-common.fullname" . }}.

Jenkins runs nonroot on a read-only root filesystem as a single-replica StatefulSet
with JENKINS_HOME on a persistent /var/jenkins_home volume. The Service exposes:

  http    {{ .Values.service.ports.http }}    web UI + REST API + /login
  agent   {{ .Values.service.ports.agent }}   inbound JNLP/TCP build agents

  {{ include "quench-common.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local

Open the UI over a port-forward:

  kubectl port-forward svc/{{ include "quench-common.fullname" . }} {{ .Values.service.ports.http }}:{{ .Values.service.ports.http }}
  # then browse http://127.0.0.1:{{ .Values.service.ports.http }}

{{- range .Values.extraEnvVars -}}
  {{- if and (eq .name "JAVA_OPTS") (contains "jenkins.install.runSetupWizard=false" (toString .value)) -}}
    {{- $wizardDisabled = true -}}
  {{- end -}}
{{- end -}}
{{- if $wizardDisabled }}
SETUP WIZARD: disabled via JAVA_OPTS (-Djenkins.install.runSetupWizard=false), so
Jenkins boots straight to a usable state with NO authentication configured. This is
fine for an internal/sandbox install but is INSECURE if exposed. Configure security
(Manage Jenkins > Security) — or remove the runSetupWizard flag from extraEnvVars to
run the guided first-boot setup instead.
{{- else }}
SETUP WIZARD: enabled. Unlock Jenkins on first boot with the initial admin password
generated inside JENKINS_HOME:

  kubectl exec sts/{{ include "quench-common.fullname" . }} -- cat /var/jenkins_home/secrets/initialAdminPassword
{{- end }}

The image is pinned by digest and signed. Verify it:

  cosign verify ghcr.io/quenchworks/images/jenkins \
    --certificate-identity-regexp 'https://github.com/quenchworks/.+' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
